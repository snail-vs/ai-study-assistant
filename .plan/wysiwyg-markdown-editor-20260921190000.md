# Markdown 所见即所得编辑器实施计划

## 目标

将笔记正文从原始 `textarea` 升级为可直接编辑渲染结果的 Markdown 编辑器，同时保持后端继续存储 Markdown 字符串，避免数据迁移。

## 设计

1. 引入 Milkdown/Crepe 作为结构化编辑内核，不在业务组件中自行处理 `contenteditable`、光标或 Markdown 转换。
2. 封装通用 `MarkdownEditor` 组件：输入/输出 Markdown、编辑器状态、保存快捷键、主题 class、可选工具栏能力均通过 props/events 配置。
3. 封装编辑器生命周期与 Markdown 序列化适配逻辑，组件卸载时销毁实例，避免笔记抽屉重复打开造成编辑器泄漏。
4. `NotesDrawer` 只负责笔记业务布局，把正文值通过 `v-model` 交给通用编辑器。
5. 增加安全的阅读渲染组件/工具函数，确保列表摘要和阅读态使用一致的 Markdown 规则。

## 兼容与边界

- API 继续接收现有 `content: string` Markdown 字段。
- 先支持标题、强调、列表、引用、代码、链接、GFM 表格/任务列表等常用语法。
- 不在第一期引入图片上传、Mermaid、数学公式等需要额外存储或执行策略的扩展。
- 使用 debounce 草稿同步但仍由显式保存触发 API 请求；中文输入法组合期间不打断更新。

## 验证

- 编辑器单测覆盖 Markdown 初始化、变更回传、销毁和快捷键。
- 笔记组件测试覆盖编辑器接线、保存/取消和异常状态。
- 运行前端完整测试、类型检查和构建。
