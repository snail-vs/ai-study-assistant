是的，而且现在已经到了必须抽象的阶段。刚才的 Quiz 报错就是模型协议兼容层缺失导致的。

目前的问题是：

```text
Agent Schema
→ 直接交给 Provider
→ 不同模型自行解释
```

正确结构应该是：

```text
Agent 业务 Schema
        ↓
统一 Structured Output 适配层
        ↓
协议适配器
        ↓
具体 Provider / Model
```

## 建议拆成四层

### 1. 业务 Schema 层

Agent 只定义业务结构：

```python
QuizDraft
KnowledgeCardPlanDraft
SideAgentResult
```

Agent 不应该关心：

- OpenAI Chat Completions；
- OpenAI Responses；
- Anthropic Messages；
- JSON Schema；
- JSON Object；
- 是否支持 strict。

### 2. 模型能力层

统一维护模型能力：

```python
@dataclass
class ModelCapabilities:
    structured_output: bool
    strict_json_schema: bool
    json_object: bool
    streaming: bool
    reasoning: bool
    max_context: int | None
```

例如：

```python
ModelCapabilities(
    structured_output=True,
    strict_json_schema=True,
    json_object=True,
)
```

注意：能力应该属于“协议 + 模型”，但不应该让 Agent 直接维护模型名称。

### 3. Structured Output 适配层

统一入口：

```python
result = await gateway.structured(
    messages,
    task="quiz_generation",
    schema=QuizDraft,
)
```

内部根据模型能力自动选择：

```text
支持 strict JSON Schema
→ 使用 json_schema

只支持 JSON Object
→ 使用 json_object + Prompt 约束

不支持结构化输出
→ 普通文本 + JSON 解析 + 校验 + 修复

解析失败
→ 重试或返回明确错误
```

### 4. 协议适配器层

当前至少需要：

```text
OpenAI Chat Completions Adapter
OpenAI Responses Adapter
Anthropic Messages Adapter
Google Gemini Adapter
```

Provider 只负责：

- 请求格式；
- 流式格式；
- 结构化输出格式；
- 原始错误转换。

Agent 不感知这些差异。

## 关键设计：不要让所有 Schema 强制 strict

当前的：

```python
strict_json_schema(schema)
```

会把所有对象的字段都加入 `required`，这对 Responses strict 模式有帮助，但会产生两个问题：

1. 可选字段失去可选语义；
2. `dict[str, Any]` 这类动态对象在不同模型中兼容性很差。

建议统一规则：

- Optional 字段：转换为 `required + nullable`；
- 动态字典：优先改成数组结构；
- `additionalProperties`：根据协议能力决定是否保留；
- 不支持 strict 的模型：降级到 JSON Object；
- 所有返回值最终必须经过 Pydantic 校验。

例如：

```python
class QuizAnswerEntry(BaseModel):
    question_id: str
    answer: str | bool | None
    explanation: str
```

比：

```python
answer_key: dict[str, QuizAnswerKey]
```

更适合跨模型兼容。

## 建议增加统一错误类型

不要把 Provider 原始错误直接散落到业务代码：

```python
class AICompatibilityError(AIProviderError):
    task: str
    model: str
    protocol: str
    strategy: str
    raw_message: str
```

前端可以根据错误类型显示：

```text
当前模型不支持结构化输出，请切换模型或使用兼容模型。
```

余额不足则显示：

```text
当前 Provider 余额不足，请更换模型或充值。
```

Schema 不兼容则显示：

```text
当前模型暂不支持此类结构化任务，请更换模型。
```

## 推荐目录结构

```text
backend/ai/
├── base.py
├── gateway.py
├── capabilities.py
├── structured.py
├── errors.py
├── protocols/
│   ├── openai_chat.py
│   ├── openai_responses.py
│   ├── anthropic_messages.py
│   └── gemini.py
└── providers/
    ├── deepseek.py
    ├── opencode.py
    └── openrouter.py
```

其中：

```text
Provider
  └── 使用某种协议
        └── 调用某个模型
              └── 拥有一组能力
```

OpenCode 仍然作为集成商维护模型来源，但模型不再直接绑定业务 Schema。
