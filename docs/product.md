
## 一、核心定义

### 1. 学习空间

用户进入系统后看到的聊天窗口，就是一个学习空间。

它负责承载：

- 一条主线学习路径；
- 多张知识卡；
- 多个旁支会话；
- 用户笔记；
- 知识卡之间的关联关系。

可以理解为：

```text
学习空间
├── 主知识卡
├── 关联知识卡
├── 旁支会话
├── 用户笔记
└── 学习进度
```

用户不是先选择一门传统课程，而是通过聊天让主 Agent 帮自己生成一个学习空间。

---

### 2. 知识卡

知识卡是系统中最核心的内容单位。

它本质上是一份结构化 Markdown 白板，类似“Markdown 形式的 PPT”，但重点不是展示，而是辅助学习和互动。

一张知识卡可以包含：

- 标题；
- 学习目标；
- 核心概念；
- 分节内容；
- 示例；
- 图表或代码；
- 小结；
- 自测问题；
- 用户笔记；
- 关联的旁支会话；
- 关联的其他知识卡。

例如：

```text
知识卡：Kubernetes 容器深入解析
├── 第 1 节：容器镜像
├── 第 2 节：Namespace 与资源隔离
└── 第 3 节：容器运行时

关联知识卡：
└── Linux 进程与命名空间
```

“章节”不再是一个独立对象，而是知识卡内部的一个内容段落或学习单元。

---

### 3. 主知识卡

主知识卡是用户当前学习的主线内容。

它具备几个特征：

- 由主 Agent 生成；
- 有明确的章节结构；
- 用户主要围绕它学习；
- 旁支知识卡从它的某个章节挂接出来；
- 主知识卡本身不会因为进入旁支而被替换；
- 用户返回时继续停留在原来的章节和位置。

因此，主知识卡就是原来概念中的“主线课程”。

但产品内部建议使用：

```text
学习空间
→ 主知识卡
→ 知识卡章节
```

而不是同时使用“课程、微课、章节、知识卡”四套概念。

---

### 4. 关联知识卡

关联知识卡是从主知识卡或旁支会话中产生的学习分支。

它可以用于：

- 补充前置知识；
- 深入解释某个概念；
- 学习相关主题；
- 展开某个复杂问题；
- 进入实践或案例学习。

它和主知识卡是平等的内容对象，只是当前学习关系不同。

例如：

```text
主知识卡：
Kubernetes 容器深入解析

关联知识卡：
Linux 进程与内核隔离本质
```

关联知识卡学习完成后，用户可以回到主知识卡，但它不会被删除或折叠成一条聊天记录，而是会保留下来，成为用户自己的知识资产。

---

## 二、Agent 定义

### 1. 主 Agent

主 Agent 是学习空间的总导师。

职责包括：

- 理解用户想学什么；
- 创建主知识卡；
- 设计知识卡的章节结构；
- 生成和更新 Markdown 白板；
- 根据用户问题调整讲解方式；
- 推进章节；
- 识别是否存在知识断层；
- 建议创建关联知识卡；
- 在关联知识卡完成后生成桥接说明。

主 Agent 负责的是：

> 课程结构、学习路径和主线连续性。

主 Agent 不负责深入处理所有旁支问题，也不应该把所有回答都直接塞进主知识卡。

---

### 2. 旁支 Agent

第一版中，旁支 Agent 可以先只是一个“围绕单个问题工作的独立助教”。

它负责：

- 理解用户当前问题；
- 在当前旁支会话中继续追问；
- 举例、类比、澄清概念；
- 识别用户缺少的前置知识；
- 建议是否生成新的关联知识卡；
- 将旁支讨论结果反馈给主线。

第二版再把它扩展成多角色聊天，例如：

```text
旁支会话
├── 解释老师：负责讲清概念
├── 苏格拉底教练：通过提问推动思考
├── 实例专家：提供案例和类比
├── 质疑者：指出理解漏洞
└── 总结者：整理当前结论
```

第二版的重点不是简单增加聊天机器人数量，而是让不同角色承担不同教学任务。

---

## 三、会话定义

### 1. 主会话

主会话是学习空间的长期对话。

它围绕主知识卡展开，负责：

- 生成知识卡；
- 修改学习目标；
- 推进章节；
- 解释当前白板；
- 处理整体学习方向。

它应该长期保留，并且与主知识卡绑定。

---

### 2. 旁支会话

旁支会话是由一个具体问题触发的独立对话线程。

```text
一个问题 → 一个旁支会话
```

用户可以在这个会话中继续追问，但它不会自动和其他问题混在一起。

旁支会话具备：

- 起始问题；
- 所属知识卡；
- 所属章节；
- 独立聊天记录；
- 当前讨论主题；
- 是否生成关联知识卡；
- 是否已经完成；
- 用户在其中记录的笔记。

例如：

```text
所属主知识卡：Kubernetes 容器深入解析
所属章节：Namespace 与资源隔离
旁支会话标题：Namespace 到底隔离了什么？
```

旁支会话可以有三种结果：

1. 普通答疑结束；
2. 用户决定生成关联知识卡；
3. 需要切换互动版进行更复杂展示。

---

### 3. 旁支会话和知识卡的关系

建议明确：

```text
旁支会话是过程，知识卡是沉淀。
```

不是每个旁支会话都必须生成知识卡。

```text
问题
→ 旁支会话
→ 普通解释
→ 结束
```

或者：

```text
问题
→ 旁支会话
→ 发现知识断层
→ 用户确认
→ 生成关联知识卡
```

这样可以避免系统把所有问题都膨胀成内容卡片。

---

## 四、界面区域定义

### 1. 顶部路径区

显示用户当前的位置和上下文关系：

```text
学习空间：Kubernetes 容器深入解析
→ 第 2 节：Namespace 与资源隔离
→ 旁支：Namespace 到底隔离了什么？
```

如果进入关联知识卡：

```text
主知识卡 / 第 2 节
→ 关联知识卡：Linux 进程与命名空间
```

它的作用是让用户始终知道：

- 我现在在哪张卡；
- 我从哪里来的；
- 当前内容和主线是什么关系；
- 返回后会回到哪里。

---

### 2. 左侧导航区

左侧展示学习结构：

```text
主知识卡
├── 第 1 节
├── 第 2 节
└── 第 3 节

关联知识卡
├── Linux 进程与命名空间
└── cgroups 资源限制

旁支会话
├── Namespace 到底隔离了什么？
└── 为什么还需要 cgroups？
```

第一版可以先用树状列表，不必实现图谱。

---

### 3. 中央主面板

中央区域是当前知识卡的 Markdown 白板。

主要展示：

- 当前章节内容；
- 代码；
- 表格；
- 引用；
- 桥接提示；
- 用户笔记；
- 学习状态。

默认展示主知识卡当前章节。

当用户进入关联知识卡时，中央区域切换为关联知识卡，但主知识卡保持原位置和状态。

---

### 4. 右侧聊天区

右侧是对话区域。

可以分为：

```text
主会话
旁支会话列表
当前旁支会话
```

用户可以：

- 在主会话中询问整体问题；
- 从某个具体问题创建旁支；
- 切换已有旁支；
- 新建旁支；
- 关闭或完成旁支；
- 从聊天内容保存笔记；
- 请求生成知识卡。

---

### 5. 用户笔记区

用户笔记应当在中央白板中始终可见或容易展开。

建议支持：

- 章节笔记；
- 知识卡笔记；
- 旁支会话笔记；
- 手动输入；
- 保存一段 AI 回复；
- 将笔记移动或复制到其他知识卡；
- AI 帮助整理笔记。

笔记的核心归属是：

```text
笔记 → 某张知识卡 / 某个章节
```

而不是只归属于聊天消息。

---

## 五、互动版定义

互动版可以作为第二版的重要能力。

它不是另一张知识卡，而是知识卡的一种展示模式。

### 普通白板模式

适合：

- 概念解释；
- 分节学习；
- 代码；
- 示例；
- 小结；
- 用户记笔记。

### 互动版模式

适合：

- 流程图；
- 对比表；
- 时间线；
- 关系结构；
- 系统架构；
- 因果链；
- 状态变化；
- 多步骤过程；
- 需要占用大屏展示的答案。

交互方式可以是：

```text
旁支会话：
“Namespace 创建进程隔离的过程是什么？”

AI 回复：
“这个问题适合用流程图展示。”

[在主面板中展示]
```

点击后：

```text
左侧主面板：
切换为互动展示

右侧聊天：
继续保留当前旁支会话
```

顶部路径可以显示：

```text
主知识卡 / 第 2 节
→ 旁支会话
→ 互动展示：Namespace 隔离流程
```

互动版的内容仍然属于当前旁支会话，但可以被保存为：

- 知识卡中的补充内容；
- 一条用户笔记；
- 一张独立的可复用知识卡。

第二版再决定支持哪些渲染协议，例如：

```json
{
  "type": "flowchart",
  "title": "Namespace 隔离流程",
  "nodes": [],
  "edges": []
}
```

第一版可以先保留扩展点，不必实现复杂互动渲染。

---

## 六、主线和旁支的交互规则

建议将规则定成这样：

1. 主线白板始终有自己的当前章节和位置。
2. 旁支会话从主线某个具体位置发起。
3. 进入旁支不会改变主知识卡状态。
4. 旁支 Agent 可以建议补充知识，但不能强制用户跳转。
5. 用户确认后，才生成关联知识卡。
6. 关联知识卡完成后，用户主动返回主线。
7. 返回主线时显示桥接提示。
8. 旁支聊天记录永久保留，但不会自动污染主线内容。
9. 用户笔记由用户主动创建，AI 只提供辅助整理。
10. 互动版只是中央面板的另一种展示状态，不改变知识卡和会话的归属。

---

## 七、推荐的整体对象关系

```text
学习空间
│
├── 主会话
│   └── 主 Agent
│
├── 主知识卡
│   ├── 章节
│   ├── 用户笔记
│   └── 关联旁支会话
│
├── 关联知识卡
│   ├── 章节
│   ├── 用户笔记
│   └── 来源旁支会话
│
└── 旁支会话
    ├── 旁支 Agent
    ├── 聊天记录
    ├── 知识断层建议
    ├── 互动版展示
    └── 生成的关联知识卡
```

最重要的概念关系是：

```text
学习空间是容器
知识卡是内容
章节是知识卡内部结构
会话是交互过程
Agent 是执行角色
笔记是用户资产
互动版是展示模式
```

## 八、版本范围

### 第一版

实现：

- 用户进入聊天窗口；
- 主 Agent 生成主知识卡；
- Markdown 白板按章节展示；
- 主会话；
- 一个问题创建一个旁支会话；
- 旁支会话持续问答；
- AI 识别知识断层；
- 用户确认后生成关联知识卡；
- 关联知识卡挂接到主知识卡章节；
- 主线和关联卡之间进行跳转；
- 返回主线时显示桥接提示；
- 用户笔记；
- 基础的知识卡和会话列表。

### 第二版

加入：

- 互动版大屏展示；
- 流程图、表格、关系图、时间线等结构化内容；
- 旁支多 Agent 角色聊天；
- 旁支 Agent 之间的讨论；
- AI 根据问题自动选择展示模式；
- 互动内容沉淀回知识卡；
- 更完整的知识卡关联视图。

这样第一版的基础模型不会被第二版推翻：互动版和多 Agent 都是围绕知识卡和旁支会话扩展。
