# 学习活动规范

## 边界

- 知识卡回答“学习什么”，章节回答“当前学什么”。
- 学习活动回答“是否理解、能否应用当前章节”。
- 活动挂在章节上，不创建知识卡，也不改变主线章节顺序。
- 本阶段只实现 `quiz` 类型的“理解检查”。`practice` 和 `lab` 只保留模型扩展位。

## 理解检查

每个章节可以按需生成一份理解检查，包含单选、判断和简答题。题目必须对应章节的教学目标，不考察正文没有覆盖的细节。

答题完成后保存尝试记录，得到逐题反馈、总分和掌握程度：

- `mastered`: 85–100
- `developing`: 60–84
- `needs_review`: 0–59

只有明确影响当前章节理解的误区，才允许触发前置知识建议；答错一道题不自动创建学习分支。

## 数据安全

活动的题面和答案键分开保存。答案键只用于后端判分和简答题评估，不通过活动查询接口返回。

## 后续扩展

```text
章节
├─ 课程内容
├─ 学习活动
│  ├─ 理解检查（quiz）
│  ├─ 应用练习（practice）
│  └─ 动手实验（lab）
└─ 学习分支
```
